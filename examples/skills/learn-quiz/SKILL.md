# 测验

测试对最近编写或接受的代码的理解程度。

## 用法

```
/learn:quiz                     # 测验上次处理的代码
/learn:quiz error handling      # 关注特定方面
/learn:quiz --hard              # 更有挑战性的问题
```

## 使用说明

1. 识别我上次处理的代码（编写、编辑或从 AI 接受的）
2. 生成 3-5 个测试不同理解层次的问题：
   - **记忆**：这段代码做什么？
   - **理解**：为什么选择这种方法？
   - **应用**：如果 X 变了会怎样？
   - **分析**：这种方法的权衡是什么？
   - **综合**：你会如何扩展它？
3. 逐个呈现问题
4. 等待我回答后再揭示正确答案
5. 每个答案附带解释，不只是"正确/错误"

## 问题类型

### 第 1 级：记忆
- "函数 X 返回什么？"
- "Y 接受哪些参数？"
- "调用 Z 时会发生什么？"

### 第 2 级：理解
- "这里为什么用 X 而不是 Y？"
- "这个模式解决了什么问题？"
- "为什么这行是必要的？"

### 第 3 级：应用
- "如果删掉 X 行会怎样？"
- "如何在此代码中添加功能 Y？"
- "如果输入 Z 会发生什么破坏？"

### 第 4 级：分析
- "这种方法的性能影响是什么？"
- "哪些边缘用例可能导致问题？"
- "与替代方案 X 相比如何？"

### 第 5 级：综合
- "你会如何重构以改善可测试性？"
- "需要改变什么来支持 X？"
- "设计一个添加 Y 的扩展"

## 关注领域

指定关注主题时（如 `/learn:quiz error handling`），优先提问以下问题：

| 关注点 | 问题主题 |
|-------|-----------------|
| `error handling` | Try/catch、错误类型、恢复策略 |
| `performance` | 大 O、优化、瓶颈 |
| `security` | 输入验证、XSS、注入 |
| `testing` | 测试用例、边缘用例、模拟 |
| `architecture` | 模式、关注分离、SOLID |
| `types` | TypeScript 类型、推断、泛型 |

## 难度模式

### 默认
- 3 个问题
- 第 1-3 级混合
- 专注于理解当前代码

### `--hard`
- 5 个问题
- 第 3-5 级
- 包含假设性修改
- 询问权衡和替代方案

## 回复格式

每个问题：

```
## 问题 1 of 3

[问题文本]

你的答案是什么？

---
（用户回复后）

### 反馈

[是否正确及原因]

**关键洞见**：[此问题测试的概念]

**相关概念**：[值得进一步探索的内容]

准备好下一个问题了吗？
```

## 测验完成后

总结：
- 得分：X/Y 正确
- 强项：[理解良好的主题]
- 需要复习：[需要重新审视的主题]
- 建议练习：[具体练习]

## 示例会话

```
用户：/learn:quiz

Claude：查看你最后的代码——用于数据获取的 useEffect 钩子。

## 问题 1 of 3

在你的 useEffect 中，你有一个空依赖数组 []。
这对 effect 何时运行意味着什么？

用户：它只在组件挂载时运行一次

Claude：### 反馈
正确！空依赖数组意味着 effect 只在挂载时运行（以及卸载时清理）。

**关键洞见**：依赖数组控制 effect 何时重新运行。

**相关概念**：无数组 vs. [someValue] 会怎样？

准备好问题 2 了吗？
```

## 给用户的提示

1. **诚实**——答错是学习机会
2. **解释你的推理**——有助于发现即使答对时存在的知识缺口
3. **追问跟进**——如果反馈不清晰，深入挖掘
4. **跟踪薄弱领域**——记下需要更多练习的主题
